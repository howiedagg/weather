## 專案目標

以中央氣象署資料製作全前端天氣 Web App，讓使用者以今天為主，連續縮放查看溫度、體感與濕度，並能回看過去一週及查看未來一週。畫面以現代簡約、容易閱讀、少文字、操作簡單、過渡流暢為目標。

## 狀態如何閱讀

| 狀態 | 定義 |
| --- | --- |
| **已確認需求** | 使用者在對話中直接提出或明確同意的方向。 |
| **已實作** | 現有程式已有此功能；不代表已通過所有裝置或真實資料驗證。 |
| **已驗證（註明範圍）** | 有實際檢查結果，並說明是示範資料、測試用資料或哪種畫面檢查。 |
| **暫行方案／設計提案** | 助理為完成第一版採用的選擇，尚未獲得使用者逐項確認。 |
| **待確認** | 需要使用者決定的產品或設計問題。 |
| **待驗證** | 需要連線、實際資料或裝置測試才能判斷的問題。 |

「已實作」和「待確認」可以同時成立。例如已有橘色溫度線，但這個配色尚未由使用者定案。

## 文件維護原則

1. 需求以 [01-需求.md](01-需求.md) 為主，工作狀態以 [06-後續工作.md](06-後續工作.md) 為主。
2. 新增或改變使用者決定時，同步更新需求與討論紀錄。
3. 驗證完成後，記錄日期、資料來源、檢查範圍及結果，再變更狀態。
4. 示範資料、官方觀測、官方預報與自行估算的體感要分別標示。
5. 文件不得保存 API 授權碼或其他憑證。

這份文件整理既有對話與現有程式，沒有重新宣告官方資料已通過實際連線驗證。
